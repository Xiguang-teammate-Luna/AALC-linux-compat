# 设计与上游接入建议

## 为什么进入游戏现有的 Proton 环境

独立 Wine 前缀中的 AALC 无法自然共享游戏的窗口／进程视图。启动器从运行中 Limbus 进程读取 Proton 工具路径和环境，通过 `flatpak enter` 进入对应 Steam 实例，再复用游戏的 Wine 前缀。它不修改游戏启动参数、汉化或 Proton 配置。

## 为什么保留 Windows AALC 并替换截图

当前实现复用官方发行包的 PyInstaller 模块及依赖，继续使用原有识别、任务、配置和输入。Windows GDI 等截图在本机 Proton 渲染路径下得到黑图；Linux 宿主用 XComposite 读取 XWayland 游戏窗口，并通过仅监听回环地址的 HTTP 服务交给 Windows PIL。按 Win32 客户区尺寸裁剪，保留原有高层截图调度、模拟器分支和锁。

该服务向本机会话开放游戏画面及通知请求，不绑定局域网地址。它没有跨用户授权机制，不应转发端口或作为远程截图服务使用。

## 补丁边界

| 文件 | 作用 |
|---|---|
| `launch_aalc.py` | 同环境启动、单实例恢复、桥接生命周期与日志 |
| `compat_bootstrap.py` | 加载官方模块，Windows 进程内部设置 `QT_QPA_PLATFORMTHEME=windows`，安装兼容钩子 |
| `capture_bridge.py` / `wine_capture.py` | 实时截图、客户区几何核对、RGB／灰度、Linux 通知；回环请求绕过 HTTP 代理 |
| `window_compat.py` | 后台输入恢复最小化游戏时避免透明和鼠标穿透 |
| `reward_compat.py` | 周常任务侧栏模板不匹配时使用限定位置的 OCR 备用点击 |
| `shop_compat.py` | 第二体系的 0／1 配置仅在运行时转换为布尔值；无效合成提示保护 |

后两项是业务兼容修补，应与平台适配分别审查；它们不是 Linux 支持的固有需求。V1.6.0 中曾使用的楼层与观测饰品补丁已在迁移 V1.6.1 时移除，改用新版官方逻辑。

## 当前实现的维护成本

启动器使用 PyInstaller 加载器内部结构，并依赖版本对应的模块及钩子名。准备工具从用户下载的官方程序中提取，不在仓库中保存这些冻结产物。上游改变打包格式或模块接口时，需要重新适配；不能只改版本号放行。

## 建议上游先接入的内容

1. 给截图和通知提供明确可替换的后端入口，使平台适配不再依赖冻结模块加载。
2. 将窗口激活、透明／穿透处理与截图实现分开，允许 Wine 环境选择兼容策略。
3. 增加 Steam／Proton 启动文档或独立启动入口，明确共享前缀的条件。
4. 平台适配与业务修复分别提交小范围 PR，逐项验证原 Windows 路径。

上游已有 [Linux 需求讨论 #416](https://github.com/KIYI671/AhabAssistantLimbusCompany/issues/416)，其中记录了前缀／窗口查找和黑图问题，也有原生 Linux 分支的探索。本方案补充的是宿主截图桥接与同环境运行的实测路径。
